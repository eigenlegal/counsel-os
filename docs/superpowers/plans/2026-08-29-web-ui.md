# Local Web UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the four-surface local web UI (chat + run record, vault, settings) served by `counsel-os serve`, plus the typed-answer text fallback, a fake provider for tests, and a settings API that edits `providers.yaml` live.

**Architecture:** A Vite/React app in `runtime/ui/` built to `runtime/ui/dist` and served as static files by the Bun server (SPA fallback, no token for assets). The page takes the bearer token from the URL fragment, keeps it in `sessionStorage`, and talks to the existing API plus a new `/settings` trio. Streaming uses `fetch` + a hand-written SSE parser. Everything is testable without a model via `serve --fake`.

**Tech Stack:** Bun 1.3.x, TypeScript, React 18, Vite 6, `marked` (markdown), `happy-dom` + `@testing-library/react` (component tests under `bun test`), Playwright (already a dep) for the e2e flow, `Bun.YAML.parse/stringify`.

**Spec:** `docs/superpowers/specs/2026-08-29-web-ui-design.md`

## Global Constraints

- Static assets are served without a token; **every** API route keeps the bearer check. The token travels only in the URL fragment and `sessionStorage` — never a query string, never a log line, never a cookie.
- `/` and the SPA fallback must never serve anything under `.counsel/` or outside `runtime/ui/dist`.
- No write path from the UI to the vault except `POST /threads/:id/approve`; `PUT /settings` writes only `providers.yaml` under `counselHome`.
- Founder rule: no review screen, no gates, no contract-shaped flow. Proposal cards are approve/reject on a file change, nothing more.
- Functional styling only (system font stack, CSS variables for light/dark via `prefers-color-scheme`, no component library). The design pass is step 5.
- UI source under `runtime/ui/src`; UI tests beside source as `*.test.tsx`; server tests beside source. Commit messages `runtime:` / `ui:` / `docs:`; no Co-Authored-By trailer.
- No subscription calls in this plan. Live check = Ollama only.

### Task 1: Typed-answer text fallback

**Files:** modify `runtime/src/core/types.ts`, `runtime/src/providers/direct.ts` + test, `claude-harness.ts` + test, `codex-harness.ts` + test, `runtime/src/loop/counsel-loop.ts` + test, `runtime/src/loop/run-record.ts` + test, `runtime/src/server/routes.ts` + `sse.ts` + tests.

**Interfaces:** `StepEvent` error variant → `{ type:'error'; message: string; text?: string }`. Direct: on `result.output` rejection, `text` = concatenation of the streamed deltas (buffer them in `run()`). Claude: on structured-output validation failure, `text = msg.result` when a string. Codex: `text = finalResponse`. `RunRecord.errorText?: string` set by `finalizeRun` from `ev.text`. Routes: when `outputSchema` is set on the step, wrap the event stream so `text` events are dropped before `sseFromEvents` and a single SSE comment line `: typed\n\n` is written first.

- [ ] Failing tests: direct (mock stream text `{"a":"no"}` with schema `{a:number}` → `error.text === '{"a":"no"}'`); Claude mapper (`result` success with invalid `structured_output` and `result:'raw'` → `error.text === 'raw'`); Codex mapper (`turn.completed` with schema, non-JSON finalResponse → `error.text`); loop (fake yielding `error` with text → record `errorText`); routes (typed step with a fake yielding `text` then `done` → no `text` frames, comment present; untyped step unchanged).
- [ ] Implement; `bun run typecheck:runtime`; `bun test`. Commit `runtime: typed-answer failures keep the raw text; typed steps do not stream raw deltas`.

### Task 2: Fake provider, `--open`, token URL, static serving

**Files:** create `runtime/src/server/static.ts` + test; modify `serve.ts` + test, `runtime/src/providers/registry.ts` (accept `extraProviders?: ModelProvider[]` and `defaultId?` override), `runtime/src/cli.ts`; `package.json` scripts.

**Interfaces:** `serveStatic(distDir: string): (req: Request) => Promise<Response | null>` — `GET`/`HEAD` only; path resolved under `distDir` with `realpath` containment (400 otherwise → return a 404 response, never throw); files under `/assets/` with immutable cache headers; anything else (incl. `/`) → `index.html` (200) when it exists, else a small built-in HTML page saying "UI not built — run `bun run ui:build`". Called by `createApp` BEFORE the auth check for non-API paths only: API paths = `/health`, `/threads*`, `/runs*`, `/vault*`, `/settings*` — everything else is static. `startServer({ fake?: FakeScript[]; open?: boolean })`: with `fake`, register `new FakeModelProvider(script)` and set `defaultId = 'fake/fake'`. CLI: `serve --fake [--fake-script file.json] [--open]`; the printed line is `counsel-os runtime on http://127.0.0.1:<port>/#token=<token> (vault: …)`; `--open` spawns `open` (macOS) / `xdg-open` (linux) detached.

- [ ] Failing tests: static (`/` → index.html 200; `/assets/x.js` → file + cache header; `/../etc/passwd` and `/.counsel/x` → the SPA shell (200), never a file — a SPA owns its own routes, so only `/assets/*` misses are 404; missing dist → placeholder 200; `POST /` → 404); routes (unauthenticated `GET /` is 200 HTML while `GET /health` is 401); serve (`--fake` → `/health.default === 'fake/fake'`; printed line contains `#token=`).
- [ ] Implement; tests; commit `runtime: static UI serving, token URL, --open, --fake provider`.

### Task 3: Settings API + registry write/reload

**Files:** create `runtime/src/server/settings.ts` + test; modify `registry.ts` + test (`writeRegistry(file, reg: RegistryFile): void` via `Bun.YAML.stringify` + tmp/rename; `loadRegistry` unchanged), `routes.ts` (mount), `serve.ts` (hold a mutable `RuntimeState { providers, router, defaultId, stepTimeoutMs }` that `createApp` reads through a getter so a reload takes effect without restart).

### Task 4: UI scaffold, API client, chat surface, run panel

**Files:** create everything under `runtime/ui/` listed above except `vault/` and `settings/` (stubs with "coming next" text); `package.json` root scripts: `"ui:build": "cd runtime/ui && bun install --frozen-lockfile && bunx vite build"`, `"ui:dev": "cd runtime/ui && bunx vite"`, `"ui:test": "cd runtime/ui && bun test"`; CI runs `ui:build` and `ui:test`.

**Interfaces:**
- `api/sse.ts`: `parseSseChunk(rest: string, chunk: string): { frames: { event: string; data: string }[]; rest: string }` — handles `event:`/`data:` lines, multi-line data, comments, partial frames across chunks.
- `api/client.ts`: `fetchJson<T>(path, init?)` adds `Authorization`, throws `ApiError { status, body }`; `streamStep(threadId, body, onEvent: (ev: StepEvent & { runId?: string }) => void, signal: AbortSignal): Promise<void>` — POST, read the body stream, feed `parseSseChunk`, `JSON.parse` each frame's data, call `onEvent`; resolves on stream end; rejects on non-200.
- `api/token.ts`: on load, if `location.hash` contains `token=`, store it in `sessionStorage['counsel-os.token']` and rewrite the hash without it (keeping any `#/route`); `getToken()` throws `TokenMissingError` → app shows the 401 message from spec §5.
- Chat state: `events: ThreadEvent[]` from `GET /threads/:id` + `runs: RunRecord[]` from `GET /runs?thread=`; sending appends a user turn and streams into a live assistant turn (`text` concatenated; `tool_call`/`tool_result` paired by id into ToolCards; `proposal` → ProposalCard; `warning`; `done`/`error` close the turn and refetch runs). Composer disabled while streaming; "Stop" aborts the fetch (server marks the run abandoned).
- ProposalCard: `POST /threads/:id/approve` → updates status; 409 → shows `expected`/`actual` hashes + a Reload button that refetches the thread.
- RunPanel: collapsed by default; badge colours by status.

- [ ] Component tests (`happy-dom`): `parseSseChunk` (split frames, partial chunk, comment lines); `ProposalCard` approve → calls API and shows "approved"; 409 → shows both hashes; `RunPanel` renders status/tools/proposals; `TurnView` groups a tool_call with its result by id.
- [ ] Build passes (`bun run ui:build`); typecheck (`tsc -p runtime/ui`); commit `ui: scaffold, API client with SSE streaming, chat with tool/proposal cards and run panel`.
