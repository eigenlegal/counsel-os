# Routing and evals, step 2 — the eval runner in TypeScript

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the eval suite runs inside the runtime — fixtures v2, five scorers, a runner through the real loop on any provider, a results record — and the Python scripts retire.

**Architecture:** `runtime/src/evals/` holds the fixture schema and loader, the scorers (pure functions over a fixture + an output), a vault preparer, a runner that drives `runStep` with the scorer's output schema, and an append-only results store under `<vault>/.counsel/evals/`. The CLI and two routes front it. The TypeScript `findings` scorer reproduces `scripts/run_evals.py` and is checked against the committed sample outputs and the saved baseline before the Python is deleted.

**Tech Stack:** Bun, zod 4, the existing loop (`runStep`), `FsVaultStore`, `ThreadStore`, the docx module (`applyRedlines`) for the redline scorer.

**Spec:** docs/superpowers/specs/2026-09-02-routing-and-evals-design.md §4, §5 (store), §9, §10, §11 step 2, §12.

## Global Constraints
- Findings scorer aggregate: recall 0.45 · precision guard 0.25 · citation coverage 0.20 · hallucination 0.10 (as `run_evals.py:153-158`), plus the severity band rule (an expected catch matches only when the finding's severity is within one band unless the catch says `severity: any`).
- Self-test bar: every shipped fixture ≥ 0.95 on `evals/sample-outputs`.
- No real model calls in tests: the fake provider only.
- Results file: `<vault>/.counsel/evals/results.jsonl`, append-only, one line per fixture run.
- Cost guard: over $1 estimated needs `confirm: true` (route) or `--yes` (CLI).
- No Co-Authored-By / Claude-Session trailers on commits.
