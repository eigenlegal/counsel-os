# The `counsel-os` binary — implementation plan (packaging step 1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `bun run build:runtime` produces one `counsel-os` binary that serves the app with the UI and the shipped content embedded, locates the vendor CLIs, never shells out to Python, and is published from CI with a smoke test.

**Architecture:** the generated modules live under `runtime/src/generated/` (git-ignored) and are referenced only from a generated entry (`runtime/src/generated/entry.ts`) that registers them into a committed registry (`runtime/src/core/embedded.ts`) and then imports `cli.ts`. The checkout never imports a generated file, so typecheck and tests need no build; the binary's entry is the generated one. `isCompiled()` reads the registry (and `$bunfs`), and every disk read at start (`serve.ts`, `cli.ts`, `mcp/stdio.ts`, `doctor/policy.ts`, the content source) asks the registry first.

**Tech Stack:** Bun `--compile`, `with { type: 'file' }` imports, the existing `ContentSource` seam, `serveStatic` over a `StaticSource`.

**Spec:** `docs/superpowers/specs/2026-09-01-packaging-design.md` §3, §8, §9 step 1.

## Global Constraints
- Nothing outside the shipped roots is embedded; `knowledge/law/frontmatter-policy.json` rides as an "extra" for doctor.
- A build that embeds zero content must fail; `init` / `update-content` on a source with zero (or fewer than the manifest's) files refuse with a sentence.
- No vendor CLI is bundled; located paths are passed to the SDKs.
- No Co-Authored-By / Claude-Session trailers on commits.
